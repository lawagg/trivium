# Техническое задание — «Тривиум»

Система сравнительного судейства двух песен.
Версия документа: 1.0.

---

## 1. Назначение

Десктопное приложение, в котором судья сравнивает две песни: двигает фейдеры
«левее / правее», выражая относительное превосходство одной песни над другой
по каждому критерию, и получает результат — победителя, проигравшего и разбор
по критериям.

Расчёт полностью выполняется внутри приложения и не показывает промежуточные
баллы во время судейства: результат становится известен только после нажатия
«Результат».

## 2. Элементы интерфейса

| № | Элемент | Описание |
|---|---------|----------|
| 1 | Блоки «Разум», «Тело», «Душа», «Арт» | Открывают фейдеры соответствующего блока |
| 2 | Поля для ввода никнеймов | Слева — первая песня, справа — вторая |
| 3 | Кнопка «Сброс» | Возврат формы в исходное состояние |
| 4 | Кнопка «Результат» | Подсчёт и вывод результата |
| 5 | Блок «Разум» | Базовый |
| 6 | Блок «Тело» | Базовый |
| 7 | Блок «Душа» | Базовый |
| 8 | Блок «Арт» | Коэффициентный |
| 9 | Блок «ОВ» | Общее впечатление, отдельно для каждой песни |
| 10 | Поле «Победитель и его ОВ» | Заполняется после «Результата» |
| 11 | Поле «Проигравший и его ОВ» | Заполняется после «Результата» |

## 3. Блоки и критерии

| Блок | Критерий | Что оценивает |
|------|----------|---------------|
| Разум [5] | Образ | Художественное наполнение текста: тропы, образы, аллюзии, панчлайны, идея |
| | Рифма | Звуковая организация: рифма, ассонансы, аллитерации, фоника |
| | Ритмика | Метрическая организация: размер, схемы, паузы, акценты |
| Тело [6] | Техника | Вокально-исполнительское мастерство: управление голосом, точность, чистота |
| | Насыщенность | Яркие выделяющиеся элементы: сложные фрагменты, эдлибы, хоры, смены подачи |
| | Соответствие | Гармония вокала и инструментала, стилевая характерность, работа на замысел |
| Душа [7] | Индивидуальность | Неповторимость исполнителя: узнаваемость, харизма, единство образа |
| | Нативность | Естественность и органичность: лёгкость, отсутствие натяжек, соразмерность |
| | Качество | Техническая и звуковая состоятельность записи: баланс, сведение, аранжировка |
| Арт [8] | Глубина | Содержательная глубина: возвращаемость, авторский мир, независимость от сезона |
| | Широкоохватность | Соответствие текущему музыкальному запросу, хитовая привлекательность |

Полные определения критериев — в `trivium/texts.py`; они же показываются
в интерфейсе при открытии блока.

## 4. Шкалы фейдеров

| Фейдеры | Центр | Край | Шаг | Числа на экране |
|---------|-------|------|-----|-----------------|
| Девять базовых критериев | 1 | 6 | 0,1 | нет |
| Глубина, Широкоохватность | 1 | 1,5 | 0,01 | нет |
| ОВ | 0 | 10 | 1 | да: шкала с числами, рисками и чёрточками |

Фейдер движется плавно и может остановиться в любом месте. Засчитывается
значение с **округлением вниз** до шага шкалы: если фейдер стоит между 2,5 и
2,55 — засчитывается 2,5.

Двойной клик по фейдеру возвращает его в центр. Фейдер можно оставить в центре,
если судья не видит преимущества.

## 5. Начисление баллов

### 5.1. Базовые критерии (девять)

* Фейдер в центре — обе песни получают по 1 баллу.
* Фейдер сдвинут к одной песне — она получает значение фейдера (от 1,1 до 6),
  оппонент — ровно 1 балл.
* Проиграв во всех девяти базовых критериях, песня получает 9 баллов.

### 5.2. Блок «Арт» (коэффициентный)

* Коэффициент получает только та песня, которая впереди по этому фейдеру;
  при положении в центре не получает никто.
* Значение фейдера — это коэффициент: 1,05 = +5% к базе, 1,5 = +50%.

### 5.3. Формулы

```
Базовый критерий                     ∈ [1; 6]

Разум = Образ + Рифма + Ритмика
Тело  = Техника + Насыщенность + Соответствие
Душа  = Индивидуальность + Нативность + Качество

База = Разум + Тело + Душа           ∈ [9; 54]

A = Глубина          ∈ [1; 1,5],   a = A − 1 ∈ [0; 0,5]
W = Широкоохватность ∈ [1; 1,5],   w = W − 1 ∈ [0; 0,5]

Итог = База × (1 + a + w)            ∈ [9; 108]
```

## 6. Общее впечатление (ОВ)

* Выставляется отдельно каждой песне: 0–10, шаг 1.
* Ввод — стрелкой вниз под названием песни.
* На определение победителя не влияет, кроме ничейного исхода.
* Используется для разрешения ничьей и для рейтинга.

## 7. Вывод результата

1. Кнопка «Результат» → все блоки сворачиваются, форма сменяется разбором.
2. Победитель и проигравший с их ОВ.
3. Радар по девяти базовым критериям: две замкнутые линии без заливки,
   точки на осях — базовое значение × коэффициент блока «Арт».
4. Списки критериев, которые каждая песня забрала у оппонента.
5. Короткий вердикт: «Ничья», «Переворот Артом», «По общему впечатлению»,
   «На грани», «Уверенная победа», «Разгром».
6. При равенстве итоговых баллов победитель определяется по ОВ.
   При равенстве и ОВ — ничья.

Баллы и коэффициенты на экран результата не выводятся.

## 8. Защита от случайных нажатий

Кнопки «Результат» [4] и «Сброс» [3] требуют подтверждения действия.

## 9. Реализация в интерфейсе

Четыре блока судейства закреплены за вершинами вращающегося тетраэдра:
вершина — это кнопка блока [1]. При открытии вершина уходит на передний план,
а от неё разворачивается панель с фейдерами; рядом показывается пояснение
критериев блока. Кнопка «Как судить?» открывает алгоритм судейства.

Сцена нарисована собственной проекцией в 2D: вращение непрерывное,
раскрытая фигура продолжает вращаться вокруг горизонтальной оси, проходящей
через выбранную вершину.

## 10. Принятые решения

| Вопрос | Решение |
|--------|---------|
| Формула блока «Арт» | Прибавка = (коэффициент − 1) × База; шаг фейдеров 0,01 |
| Название критерия «Атмосфера» | Переименован в «Глубину» с новым определением |
| Показ коэффициента «во сколько раз сильнее» | Убран — на экране результата нет чисел |
| Показ баллов по критериям | Убран; остаются только факты превосходства |
| Визуальный стиль | Графит и латунь, единый цвет вершин, непрерывное вращение |
| Схема интерфейса | Блоки раскрываются из вершин тетраэдра |

## 11. Сохранение результата

По требованию о прозрачности офлайн-судейства в экране результата есть кнопка
«Сохранить»: она делает JPEG-снимки каждого из четырёх блоков вместе с пояснением
критериев и отдельный снимок страницы результата, складывая их в выбранную папку.
Имена файлов подставляются из названий песен.

## 12. Не реализовано

* Экспорт результата в машиночитаемом виде (JSON).
* Сохранение истории оценок между запусками.
